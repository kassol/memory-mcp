# Design System: 记忆登记簿 (Memory Registry)

The console is a quiet working surface for one person. It reads as a modern editorial tool rather than a generic admin dashboard: porcelain ground, graphite ink, a single deep-pine accent, hairline borders, soft elevation only where something is raised. The earlier shadcn/ui default look (2026-10-31) and the records-ledger direction (2026-10-30) are retired.

Source of truth: `web/src/index.css` (palette, type stacks, base surfaces), `web/src/components/page.tsx` (header, body, states), `web/src/shell.tsx` (shell), and the page files. Components in `web/src/components/ui/` are generated by the shadcn CLI and stay as generated; the theme variables and page-level layout carry the look.

## Theme

Light:

- Ground `#F6F6F3`; surface `#FFFFFF`; raised selected row `#FFFFFF` with a soft shadow.
- Ink `#17181A`; muted `#666762`; hairline `#E9E8E3`; input line `#DEDDD7`.
- Accent deep pine `#245C4F`, soft pine `#E6F0EC`, pine ink `#1C4A3F`.
- Status: success `#4F7A5E`, warning `#A9742A`, destructive `#B42318`.
- Charts: pine `#245C4F`, amber `#C08A3E`, slate `#7F8FA6`, clay `#C06A5F`, sage `#8FAF9A`.

Dark:

- Ground `#0B0C0B`; surface `#171918`; popover `#1A1D1B`; raised `#1F231F`.
- Porcelain text `#EDEBE5`; muted `#A0A29B`; hairline `#2A2E2A`; input `#333833`.
- Lifted pine `#7AAD9D`; soft pine `#1D2E29`.
- Charts lift one step: `#7FB3A2`, `#D6A85A`, `#A8B6C9`, `#D98A7C`, `#9DBFA9`.

Both: `--radius: 0.5rem` so panels land at 11.2 px and controls at 8 px. Borders are hairlines, not frames. Elevation is declared once per element: raised rows use a soft shadow; panels use a border. Cards never float on both. An inline script in `index.html` applies the saved theme before React mounts, so a dark session never flashes light.

Type: Geist Variable with a PingFang / Hiragino / YaHei CJK fallback. Page title 22 px semibold at -0.02em; section title 13 px medium; body 13–14 px; metadata 11 px; table numerals tabular. Monospace only for entity keys, setting keys and values that are code. No display serif, no all-caps labels.

Status is carried by a 6 px dot plus a word: current / finished / success use the success or pine dot, waiting uses amber, failure uses red, inactive uses a 40 % muted dot. Pills are reserved for filters and small counts. Primary actions are solid pine; secondary actions are outline; destructive is a tinted destructive button or red text. Settings save buttons are outline until the row is dirty, then solid.

## Layout

- Shell: `SidebarProvider` with a porcelain sidebar (a sheet below 768 px) and `SidebarInset`. The brand is a graphite rounded square with 记 and a pine dot, the product name, and a small MEMORY REGISTRY line. Navigation is one rail split into 审阅 and 系统 groups; the active item is a white raised row with a pine icon and `aria-current="page"`. Footer: appearance cycle and sign out.
- Page header: 64–71 px, sidebar trigger, page title 22 px, page facts or actions on the right. No description by default: titles carry the page, and repeated explanations are omitted. No vertical separator.
- Page body: centered `max-w-[1180px]`, 16 px gutters on phones and 32 px from md, 32 px vertical rhythm.
- Docket: 288 px queue on desktop with a sticky filter header (全部 / each kind with counts, the active chip marked), a selected white card with a soft shadow, and a compact row (case number, kind, key, date, two-line summary). The case is a single scroll column: a title row (case number, kind, queue position, key), the check opinion clamped to two lines with an 展开 control, a collapsible sentence-level 对比摘要, then the two record panels side by side from xl, then the ruling bar pinned to the bottom of the pane (保留甲/归档乙 pair shortcut, 上一件 / 下一件, 判为误报, keyboard hints). The open case is in the address (`?case=`), so a refresh or a shared link returns to it; J / K update the address too. 判为误报 opens a confirmation dialog because a dismissed finding is not reported again. Phones show the queue until a case opens, then a 返回列表 ghost button. An empty kind filter keeps its active chip and offers 查看全部.
- Records: underline tabs 档案 / 检索记录; a toolbar with search, key filter, type select and a phone-only sort select (最新 / 最早 / 最久未更新 / 最近更新 / Key A–Z); a bordered table on desktop (key, content, written, valid from; the type is carried by the key prefix and the filter; sortable headers; 50 rows a page; header sticky from lg; dates are 月-日 时:分 and add a two-digit year for older records); cards on phones. Paging includes first and last buttons beside 上一页 / 下一页. Filters, the sort, the page, the search text and the 档案 / 检索记录 view live in the address (`q`, `type`, `key`, `sort`, `page`, `view`); `page` is 1-based, so a link reads naturally. Opening a record adds `memory` and a back step closes it while every filter stays. Search results highlight the matched terms in the key and the content with a quiet pine wash; `/` from anywhere focuses the search field, which shows a `/` key hint when empty. A stale page link says 这一页没有记录 and offers 回到第一页. A row opens a right sheet with a sticky header, the record panel and a vertical version timeline. Provider, token and maintenance tables become card lists on phones instead of scrolling sideways.
- Overview: a full-width 待审发现 band (count and kind breakdown only) then two secondary panels 记忆 and 维护; one 近 30 天 panel with two charts — 写入与召回 together, 召回耗时中位数 beside it; then Provider, 最久未更新的记忆 and 访问令牌 panels; Provider and token panels link into their settings tabs. Charts carry a visually hidden text summary for screen readers.
- Maintenance: a schedule/run panel with the last round's status; a running round shows elapsed time, updated every second. Then a ruled history table with right-aligned duration, model calls and findings; errors show a short human summary with the raw text behind 详情.
- Settings: vertical rail of numbered sections on desktop, a 3×2 tab grid on phones; the active tab is in the URL (`?tab=`) so the page is linkable and back/forward work; the default 参数 tab keeps a clean `#/settings`. The page is not rebuilt when the tab changes, so an unsaved numeric draft survives a tab switch. One surface per section. A setting row shows the label, the source only when it is not the default, the control and its range; the description, recommended value, key and default value sit behind a 说明 disclosure. Advanced rows keep one visible sentence of context. The save control appears only after a row changes.
- Sign-in: split screen. Ink panel with the product mark, a large statement and three quiet facts; the form sits on the porcelain side. On phones the ink panel is hidden and only the mark and form remain. Secret fields have an eye control that shows or hides what is typed.

## Components

- Record panel: bordered 11 px panel, optional 甲/乙 circle, monospace key with a copy button, a copy-full-text button beside the status badges, metadata line, status dot, full text (never truncated in panels), and a footer pinned to the bottom with 改正 (outline) and 归档 (ghost destructive). Correct and archive open inline forms with a reason and a confirm action.
- Version timeline: vertical hairline with a pine dot for the current version, mutation badges, full text; older versions muted.
- Tables: 11 px muted headers, 60 % hairlines, no zebra, hover row tint, selected row accent wash; cells align top; numeric columns right and tabular. Only the active sort column shows an arrow; inactive arrows appear on hover or keyboard focus.
- Charts: 96 px high, hairline grid, no animation, one pine series and one amber series, latency in slate.
- Accessibility: each page title receives focus after a route change; a polite live region announces the case number, kind and queue position when J / K or a click opens another case.
- States: skeletons in the shape of the page (overview band and cards, docket queue and case, records table), destructive alert with retry, dashed empty panel with a muted icon, route error boundary, a 404 page with the normal page header, and sonner toasts bottom center on desktop / top center on phones. The session check shows a brand mark only after 250 ms, and a failed check offers 重试 instead of a blank page. Route content fades in over 180ms unless the system asks for reduced motion.
- Dialogs and sheets use the shadcn defaults with the porcelain palette; no custom modal shells.
- Refresh is one shared icon button (概览 / 待审 / 维护) that turns while its query runs. Phone buttons and icon buttons have a 40 px target; switches keep their native 32 × 18 shape because their row label is also a target.

## Identity

- Document title is `<page> · 记忆登记簿` (登录 when signed out), so tabs and history name the page. Away from the docket, a pending count leads the title (`(33) 档案 · 记忆登记簿`) so a background tab still reports the queue.
- The favicon is the registry mark: a graphite rounded square, three porcelain rules and a pine dot, inlined as SVG.
- `theme-color` follows the system light / dark ground.

## Rules

- Memory text is untrusted: render as text only. ESLint rejects `dangerouslySetInnerHTML` and `innerHTML` everywhere, including generated components. The generated chart component writes static CSS variables into a `<style>` tag; the rule allows exactly that. API keys show only the last four characters.
- Show the full memory text in panels and history; only list rows and table cells clamp to two lines.
- One primary action per decision point. Secondary actions are outline or ghost; destructive actions are tinted.
- Interface language is Chinese; strings inside generated components that users can see or hear are translated in place.
- Do not add gradients, glass, texture, stamps, crosshairs or ornamental rules. The identity comes from palette, type scale, spacing, hairlines and the one pine accent.
- Generated components in `web/src/components/ui/` stay as generated; change the look through `web/src/index.css` tokens and page layout, never by editing generated classes.
